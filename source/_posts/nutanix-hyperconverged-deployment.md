## 什么是超融合

传统架构是计算和存储分离：

- 计算层：VMware/Hyper-V 虚拟化
- 存储层：SAN/NAS 集中存储
- 网络层：光纤通道/iSCSI

超融合把这三层融合到一台服务器上：

- 每台服务器同时提供计算和存储
- 通过软件定义的方式池化资源
- 横向扩展，加节点就是加容量和性能

## Nutanix 架构原理

Nutanix 的核心是分布式存储引擎 AOS（Acropolis Operating System）：

**1. 数据分片**

数据被切分成固定大小的块（默认 4MB），分散存储在集群各节点上。

**2. 副本策略**

每个数据块默认有 2 个副本，分布在不同节点。节点故障时自动重建副本。

**3. 元数据管理**

用 Curator 服务管理元数据，记录每个数据块的位置和状态。

**4. 数据局部性**

优先把数据放在访问它的 VM 所在节点，减少网络开销。

## 部署实战

洹拓科技在某企业部署 Nutanix 集群时，采用了 3 节点起步的方案：

**硬件配置**

每节点：
- CPU：2× Intel Xeon Gold 6338（32 核）
- 内存：512 GB DDR4
- 系统盘：2× 480GB SSD（RAID 1）
- 缓存盘：2× 1.92TB NVMe SSD
- 容量盘：6× 8TB SAS HDD
- 网络：2× 25GbE SFP28

**软件安装**

1. 用 Foundation 工具发现节点
2. 创建集群，配置集群名称和 IP
3. 安装 AOS 和 AHV（内置虚拟化）
4. 初始化 Prism（管理界面）

**关键命令**

```bash
# 查看集群状态
cluster status

# 查看存储池
ncli pool list

# 查看数据冗余
ncli cluster get-replication-factor

# 添加许可证
ncli license add -file license.key
```

## 运维要点

集群上线后，日常运维关注以下几点：

**1. 容量监控**

- 存储使用率超过 70% 告警
- 内存使用率超过 80% 告警
- CPU 使用率持续高于 75% 考虑扩容

**2. 性能优化**

- 热数据放在 SSD 层
- 冷数据自动迁移到 HDD 层
- 开启压缩和去重节省空间

**3. 高可用配置**

- 副本因子设为 2 或 3
- 配置故障域（Fault Domain）
- 定期做故障演练

**4. 备份策略**

- 用 Leap 做 VM 级备份
- 关键数据异地备份
- 定期测试恢复流程

## Nutanix vs 其他方案

在为新乡企业选型时，我们对比过几个主流方案：

**Nutanix**

优点：
- 部署简单，2 小时上线
- 管理界面友好
- 内置虚拟化（AHV）免费

缺点：
- 硬件兼容性列表有限
- 授权费用较高

适合：中型企业私有云、VDI 场景。

**VMware vSAN**

优点：
- 生态成熟，兼容性好
- 和 vSphere 深度集成
- 功能丰富

缺点：
- 授权费用高
- 配置复杂

适合：已有 VMware 环境的企业。

**开源方案（Ceph + OpenStack）**

优点：
- 完全免费
- 灵活性高
- 社区活跃

缺点：
- 部署复杂
- 运维成本高
- 需要专业团队

适合：有技术能力的互联网企业。
