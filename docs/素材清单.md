# 官网素材清单（填完我直接改进页面）

评审提的四件事——案例单薄、首页像一次性填充、没有团队和技术栈、没有客户评价与合作案例——
结构和版式我都能立刻搭出来，缺的是**只有你手里才有的事实**。我不替你编：
数字、客户名、人名、评价一旦写进对外官网，就是广告法意义上的宣传内容，
被抽查或被对手举报时拿不出证据，代价比"页面单薄"大得多。

下面每一项，能给多少给多少，给不了的直接划掉，我就把对应板块关掉而不是留空壳。

---

## 一、案例（最需要，2-3 个就够）

模板已经做好：`hexo new case "案例标题"` 会用 `scaffolds/case.md` 生成带字段的草稿。
每个案例给我这几项：

| 字段 | 说明 | 举例（虚构，仅示意格式） |
| --- | --- | --- |
| 客户 | 名称或脱敏说法 | "辉县某机械制造企业" / "XX 公司"（要实名需授权） |
| 行业与规模 | 一句话 | 汽车零部件，约 200 人，3 条产线 |
| 原来的问题 | 有原始数字最好 | 人工目检漏检率高，每班 2 人全检 |
| 我们做了什么 | 方案要点 | 视觉检测工位 + 缺陷库 + 产线看板 |
| 结果 | **可公开、能举证**的数字 | 漏检率、人力、节拍、回本周期 |
| 周期 | 从进场到验收 | 6 周 |
| 配图 | 现场照片或系统截图 | 2-3 张，横版优先 |
| 能否署名 | 客户名/logo/负责人评价是否可公开 | 可 / 仅脱敏 / 不可 |

## 二、团队（对应"没有团队介绍"）

首页 team 板块现在是关着的（`_config.hexo-theme-xongyi.yml` 里 `team: enable: false`），
给我这些就开：

- 3-6 人：姓名（或化名）、职务、一句话擅长方向、工作年限（可写区间）
- 每人一张正装或工作照，方图，512x512 以上
- 一句团队规模的事实：几个人、分几个方向、是否有驻场能力

## 三、技术栈（对应"没有技术栈展示"）

关于页已经有一版技术栈标签墙，但那是**我按常见 AI 交付栈写的，需要你核对**：

- 删掉你们实际不用的（比如 vLLM、K8s、工业相机对接这类具体项）
- 补上真实在用但我没写的（模型、框架、向量库、云平台、国产芯片适配等）
- 有没有可写的资质/认证：厂商认证工程师、软著、ISO、专精特新、高新等
  （这些是最硬的信任状，比任何形容词有用）

## 四、客户评价（对应"没有评价"）

必须是真实、可举证的。给我：原话 + 姓名/职务/单位 + 是否同意公开。
拿不到授权就先不做这一栏。我不会代拟、也不会把评价写成"客户纷纷表示"这种没有出处的话。

## 五、可公开的数字（对应"没有具体数据"）

首页数字条现在用的是描述自身结构的诚实数字（6 大业务方向 / 3 条产品主线 / 4 个交付阶段），
换成业务数字更有说服力，但要有出处：

- 服务商户/企业数量、累计交付项目数、团队人数、成立年份
- 设备布放台数、覆盖乡镇/园区数量
- 任何一个数字，请同时告诉我它能在合同、验收单或后台数据里对上

## 六、首页"像一次性填充"这件事

这是上一轮把 82 篇文章日期统一到 10-24 造成的，两种走法你选一个：

1. 按每篇文章正文里的事件时间，把发布日期铺开到过去 6-8 周（首页看起来是持续更新，
   但所有文章 URL 会再变一次；站点还没提交搜索引擎，代价小）
2. 保持全部当天，接受"集中发布"的观感（URL 不再变动）
